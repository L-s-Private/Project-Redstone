# 規約とBANのリスク調べ（2026-10-24 時点）

STATIC ARC を使う配信者が、TikTok・マイクラ・使っている仕組みの規約で、どのくらい危ないのかを調べたまとめです。
**法律の専門家の判断ではありません。** 規約は変わるので、配る前・有料にする前にもう一度確かめてください。

---

## 結論（先に）

| リスク | 起きやすさ | ひとこと |
|---|---|---|
| アカウントそのものの永久BAN（ツールを使っただけで） | **低い** | 他のツール（TikFinity など）を含め、「つないだだけでBAN」の報告は見つからなかった。ただし規約上は「自動のしくみで TikTok にアクセスするのは禁止」とあり、ゼロではない |
| **ギフトBAN（収益化の制限）** | **中〜高（配信者のふるまい次第）** | いちばん現実的なリスク。妨害配信というジャンルそのものが「ギフトと引き換えに何かする」に近い。言い方・画面の文字で危なさが大きく変わる |
| 放置・自動配信あつかいでのLIVE制限 | 低い（ちゃんと遊んでいれば） | 配信者がいて遊んでいれば当てはまらない。寝落ち・離席はNG |
| マイクラ（Mojang）の規約 | 低い（無料で配るなら） | MODは無料ならOK。**有料版でゲームの中の機能を解放するのは危ない**（前回の調べと同じ） |
| つなぐ仕組み（Euler Stream）の規約 | 中（お金の話になったら） | 無料の範囲で、各PCから使う分には今は問題が出にくい。有料で配るなら書面の契約が要る可能性 |
| 部品のライセンス（tiktok-live-connector） | 低〜中 | 「AGPL＋追加の条件」。PCで動くアプリに組み込むのは許されている。**サーバーで代わりにつなぐサービス**にすると条件が変わる |

**他のツールと比べて：** TikTok に「ライブのギフトを読む公式の入口（API）」はなく、TikFinity・StreamToEarn・妨害マイクラなど**同じジャンルのツールは全部、非公式のつなぎ方**です。つなぎ方の危なさは STATIC ARC も他と同じ。差がつくのは「配信者がどう使うか」と「ツールがどう案内するか」です。

---

## 1. TikTok の規約

### 1-1. 利用規約（Terms of Service、2025-12-01 更新）
出典: <https://www.tiktok.com/legal/page/row/terms-of-service/en>

- 第5条で禁止：「自動のスクリプトで情報を集めたり、サービスとやりとりしたりすること」（use automated scripts to collect information from or otherwise interact with the Services）
- 同じく禁止：リバースエンジニアリング、書面の許可なしの商用利用
- TikTok は「いつでもアカウントを無効にできる」と書いている

→ 非公式のつなぎ方（tiktok-live-connector）は、**文字の上ではこの禁止に当たりうる**。これは TikFinity など全ツール共通。
→ ただし、つなぐのは「公開されているライブの情報を読むだけ」で、配信者のパスワードは使わず、配信者のアカウントで何かを操作するわけではない。

### 1-2. アカウントと機能のルール（Accounts and Features、2026-08-25 公開・**2026-09-24 から有効**）
出典: <https://www.tiktok.com/safety/en/policies-and-engagement/accounts-features>

- 「LIVE の配信者は、配信中に起きたことすべてに責任がある。**外部ツールを使っていても同じ**」
- 「外部ツールで問題が何度も起きると、LIVE や LIVE の機能が制限されることがある」
- 違反をくり返す・重い違反・処分逃れは、アカウントBANになりうる
- 「LIVE Gaming：配信者は LIVE Studio **や外部ツール**で画面を配信できる」（外部ツールを使うこと自体は前提にされている）

→ ツールが出す文字や絵（ギフト通知・ギフト表など）も、**配信者の責任**としてあつかわれる。

### 1-3. ライブ収益化ガイドライン（LIVE Monetization Guidelines）
出典: <https://www.tiktok.com/live/creators/en-US/rules_and_guidance/live_monetization_guidelines>（2026-10-24 にブラウザで全文を確認）

収益化（ギフトなど）が止められうる例のうち、関係が深いもの：

- **フェイクエンゲージメントとギフトベイティング**
  - ギフトを増やすために、だましたり、**機械的にくり返し求めたり**する
  - 「**エンゲージメントと引き換えに**いいね・フォロー・ギフトを差し出す」ような、作られたやりとり
  - 視聴者の気持ちや義理につけこんでギフトを迫る
  - 2つの意見を並べて「どっちかにギフトを」とだけ言う
- **作られた・自動のライブ**：「AI や**外部ツールで主に動かしていて、配信者がちゃんと関わっていない**」もの
- **質の低いライブ**：目的のない同じ動作のくり返し、寝落ち・放置、止まった画面

処分：アプリ内の警告 → **ギフトなど収益化機能の一時的な制限** → くり返すと**永久の制限**。お知らせから異議申し立てができる。確認場所は「クリエイターツール > LIVE センター > ルールとガイダンス > 制限」。

→ 「ギフト1つでTNT」は、**エンゲージメントと引き換えにギフトを求める形に見えやすい**。一方で、ガイドラインは「ギフトで何かが起きる仕組み」自体を名指しで禁止してはいない。**どう求めるか（連呼・条件の提示・あおり）**が判断のポイントになっている。

### 1-4. 配信者の現場の声（非公式。うのみにしない）
- マイクラ妨害配信の運営者のnote（2026-04-10）：<https://note.com/az_aka/n/n8d7e319cf6ff>
  - 妨害配信は「基本的に大丈夫」という見方。危ないのは、ギフト名を連呼する・「〇〇を送ってくれたら〇〇する」と条件を言う・お金の事情を話す、など
  - 筆者の見聞きした例として「**ギフトと行動を結びつける文字テロップ**を出していた配信者がギフトBANされた」という話がある（同じことをしてもBANされない人もいる、とも）
  - ギフトBAN中は収益が半分・おすすめに出にくくなる、10分〜1週間とのこと（公式の数字ではない）
- TikTok LIVE事務所のnote（2025-09-12）：<https://note.com/chadult/n/n81da191d4700>
  - 妨害配信は「ギフトBANの可能性が高い諸刃の剣」として**すすめない**立場
- 英語の解説（2026-09-04 更新）：<https://streamer.guide/guides/tiktok-live-rules>
  - ギフトを頼むこと自体はOK。「取引に見える形」でコンテンツをギフト次第にすると問題
  - 「ギフトでルーレット」は**賭けごとになると**禁止
  - ボットが違反したら、処分は配信者に来る。違反の記録は90日で消える
  - 2026年は放置・止まった画面の取り締まりが強くなった

## 2. 他のツールとの比べ

| ツール | つなぎ方 | 値段 | 規約・BANについての書き方 |
|---|---|---|---|
| **STATIC ARC** | tiktok-live-connector（非公式）＋Euler Stream。パスワード不要 | 無料（有料版は後で） | 「公式ではない」の注意あり（アプリ・サイト） |
| TikFinity（<https://tikfinity.zerody.one/>） | 同じ作者たちの非公式のつなぎ方 | 無料 | 「TikTok とは関係ない」だけ。BANの話はなし。利用者は非常に多い |
| StreamToEarn | ギフトなどを横取りしてゲームへ送る（方法は非公開） | 月$19〜36程度・無料版あり | 規約の説明は見つからず |
| 妨害マイクラ（LIBERTAS、<https://bougai.libertas-group.co.jp/>） | 書いていない | β中は無料、のち月3,980円 | TikTok・Mojang の規約やBANについての注意は**なし** |
| TT Interactive（マイクラ用サーバー＋プラグイン） | TikFinity 経由でマイクラのコマンドを打つ | 無料 | 特になし |
| GGTK など事務所のツール | 非公開 | 所属者は無料 | 特になし |

- TikTok にはライブのギフトを読む**公式の入口（API）がない**（tiktok-live-connector の説明にも「TikTok は公式の API を出していない」とある）。そのため**このジャンルのツールは全部、非公式**。
- 「このツールを使ったからアカウントBAN」という、はっきりした報告は見つからなかった（TikFinity を含む）。
- 公式に認められたツール・提携の仕組み（ギフトで動くゲームの公式プログラム）も見つからなかった。

**STATIC ARC の立ち位置**
- つなぎ方の危なさは、他のツールと**同じ**。
- マイクラの「MOD」として動き、サーバーのコマンドを外から打つ形ではない。マイクラ側の問題は出にくい。
- 規約の注意を書いているぶん、何も書いていないツールより**正直**。
- 一方で、「**ギフト表**」（どのギフトで何が起きるかを配信画面に出す部品）は、1-4 の「ギフトと行動を結びつける文字テロップ」に当たる見た目。同じジャンルの他のツールも普通に出しているが、**ギフトBANのきっかけになりうる**部品だと知っておく。

## 3. マイクラ（Mojang / Microsoft）
2026-10-23 に EULA と使用ガイドラインを確認済み（<https://www.minecraft.net/ja-jp/eula>、<https://www.minecraft.net/ja-jp/usage-guidelines>）。

- 自分で作った MOD は自分のもの。ただし「**売ったり、お金を得ようとしたりしない**」限り
- MOD は、「ゲームの外のもの（お金を払ったかどうか等）を確かめて、ゲームの中の機能を変える」ものであってはいけない
- 必ず書くこと：「NOT AN OFFICIAL MINECRAFT PRODUCT. NOT APPROVED BY OR ASSOCIATED WITH MOJANG OR MICROSOFT.」（**アプリ・サイトに記載済み**）
- 配信や動画で収益を得ることは、ガイドラインで認められている

→ 無料で配るぶんには問題は小さい。**有料版でルールの数やランダムなど「ゲームの中で起きること」を増やすと、2番目に当たるおそれ**。有料にするなら、有料で解放するのは配信画面の見た目・分析・履歴など**ゲームの外のもの**だけにするのが安全。

## 4. つなぐ仕組みの規約

### 4-1. Euler Stream（接続の署名をするサービス、2026-09-02 更新）
出典: <https://www.eulerstream.com/terms>

- 無料の範囲を超えたら、クレジットカードの登録が必要（§2.1）
- 7.2(f)：他人の分のリクエストをまとめて代わりに送るのは禁止
- **7.5：転売・ホワイトラベル・組み込み（embedded）・OEM は、別の書面の契約が必要**
- 使うのは自己責任（§6.1）

→ 今の STATIC ARC は、配信者それぞれの PC から無料の範囲で直接つなぐので、まとめて送ってはいない。ただ、アプリに組み込んで配ること自体が「embedded」に当たる可能性はある。**有料版を出す前に、Euler Stream に問い合わせる**（前から決めていたとおり）。

### 4-2. tiktok-live-connector のライセンス（今回新しくわかったこと）
アプリの部品 `tiktok-live-connector`（v2.5.0）のライセンスは「**AGPL-3.0＋追加の条件**」。

- 第18条：アプリに組み込んでも、アプリ全体を AGPL にしなくてよい（**商用でも可**）。ただし第19条に当たらない場合だけ
- 第19条：**商用・ソースを公開しない・ホスティングの SaaS**（WebSocket の中継・データを取る API・管理されたホスティングを**ネットごしに他人に提供**するもの）に使うと、第18条の例外がなくなり、AGPL を全部守る必要がある
- 第21条：TikFinity と Euler Stream は例外

→ STATIC ARC は**配信者の PC の中で動くアプリ**なので、第18条の範囲と読める。
→ **気をつけること：**
  - 将来「サーバーで代わりにつないで、ギフトを配る」形（クラウド版など）にすると第19条に当たる
  - 第19条の「commercial, closed-source, or hosted SaaS」は読み方があいまい。有料版を出す前に、作者（Zerody / Isaac Kogan）か専門家に確かめると安心
  - 配る exe には、この部品のライセンス文（LICENSE）を一緒に入れておく

## 5. 配信者がギフトBANを避けるために（ガイドに書くとよいこと）

公式ガイドラインと現場の声から、配信者に伝えるとよいこと：

1. **ギフト名を連呼して「送って」と頼まない。**「〇〇を送ってくれたら〇〇する」と口で約束しない
2. **遊ぶことが主役。** ギフトが来たら盛り上がる、くらいの温度にする。黙って同じ作業をくり返さない
3. **寝落ち・長い離席はしない。** 離れるなら配信を切る（「一時停止」だけで放置しない）
4. **お金の事情を話してギフトを求めない。** 「どっちのチームにギフトを」だけの対決にしない
5. **ギフト表は出しすぎない。** 出すなら「視聴者が遊び方を知るための表」として、あおる言葉を足さない
6. **ランダムの妨害を「ギャンブル」のように見せない。** 視聴者が何かをもらえる・賭ける形にしない
7. 処分が来たら、お知らせから**異議申し立て**。「LIVE センター > ルールとガイダンス > 制限」で中身を確かめる
8. 18歳未満は配信もギフトもできない（TikTok のルール）

## 6. STATIC ARC としてやるとよいこと（提案。まだ何も変えていない）
- 公式サイトのガイドと利用規約に、5. の内容と「アカウントの処分は自己責任」をはっきり書く
- アプリの「はじめの準備」か「配信」の画面に、ギフトBANの注意への短いリンクを置く
- 有料版を出す前に：Euler Stream への問い合わせ、tiktok-live-connector の第19条の確認、有料で解放するものを「ゲームの外」だけにするかの判断
- 配る exe に、使っている部品のライセンス文をまとめて入れる
